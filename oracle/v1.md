# Reference set v1: provenance

The corpus oracle of `spec/03-oracle.md`: the daily NAV path of every strategy of the Papers
With Backtest catalogue, produced by the reference engine (backtrader) in the 2026-11 grand
recalcul. Built on 2026-11-19 by `tools/oracle/build_reference.py` from the campaign's merged
table, **without re-running anything**: the NAV values are the campaign's own floats.

## Data revisions

The campaign ran online: pwb-toolbox asks the Hub for each dataset's current revision once per
process, so a run read the last commit of each dataset made before it started. The manifest
gives each run its **data epoch** (`data_epoch_utc` = end stamp minus duration) and
`hub_commits.json` holds the commit history (sha and time, no message) of the organisation's
170 datasets, fetched on 2026-11-19. `tools/oracle/pinned_hub.py` pins every dataset to its
revision at the epoch -- price tables and cost tables alike -- and downloads that revision if
the cache lacks it, so a replay reads what the reference read on any machine, with no frozen
cache to carry around.

Checked: two references re-run on backtrader at their pinned epoch (Mac, 2026-11-19) give the
reference NAV bit for bit (max relative difference 0.0, cost tables loaded).

Limits, recorded per row:

* `hub_moved_during_run`: the datasets committed while the run was going (76 references); the
  revision such a run read depends on when it first touched the dataset. Most are prediction
  market and insider tables the run may not read. The CI subset excludes them.
* A Hub history squash (`super_squash_history`) on a dataset deletes the revisions this set
  points at; the references reading it then need regenerating (below).
* The campaign's `measured_at` is written after the run; a run that waited on a guard before
  starting has an epoch slightly late. Checked harmless where it matters: no CI-subset run
  has a commit of any dataset in its window.

## Earlier Tradewind verdicts

`tw_parity` is the verdict of the parity passes of November (tradewind #27/#29 era):
identical 4 032, divergent 105, error 16, none 46. `tw_parity_on_this_measure` says whether
that verdict was computed on this very measurement (3 516) or on an earlier one (the
0.1.52 re-measures and a few fall-backs). The runner calls a divergence *expected* only when
it repeats a verdict recorded on this measurement; anything else fails.

## Regenerating (v2)

A semantic correction of chantier 4, a new pwb-toolbox or a squashed dataset makes a new
set. Run the strategies on the reference engine in its own environment
(`tools/oracle/run.py --engine backtrader --python <oracle env>` writes their NAVs), merge
them into a campaign table, build with `build_reference.py --version v2`, upload, and write
`oracle/v2.lock.json` plus a per-strategy delta against v1.
